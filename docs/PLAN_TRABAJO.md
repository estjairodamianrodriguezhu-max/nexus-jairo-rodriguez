# Plan inicial de trabajo

Este plan es una base para que el equipo acuerde el alcance real del proyecto. Marca una tarea como completada solo cuando esté revisada.

## Fase 1 — Inventario y requisitos

- [ ] Revisar todos los archivos y carpetas actuales.
- [ ] Definir el problema que resolverá NEXUS y sus usuarios.
- [ ] Escribir los requisitos funcionales y no funcionales.
- [ ] Definir los entregables y criterios de aceptación del próximo hito.

## Fase 2 — Diseño

- [ ] Dibujar el diagrama de clases.
- [ ] Definir las responsabilidades de cada clase.
- [ ] Documentar los flujos principales.
- [ ] Elegir y documentar la estrategia de persistencia, si el sistema la necesita.

## Fase 3 — Implementación

- [ ] Preparar la solución y comprobar que compila.
- [ ] Implementar las clases y reglas acordadas.
- [ ] Validar entradas y manejar errores.
- [ ] Separar interfaz, lógica del negocio y acceso a datos cuando corresponda.

## Fase 4 — Pruebas y documentación

- [ ] Probar los casos de uso principales.
- [ ] Corregir errores detectados.
- [ ] Actualizar el README con instrucciones comprobadas.
- [ ] Preparar capturas, diagramas o manuales exigidos por la materia.

## Fase 5 — Entrega

- [ ] Revisar que no haya contraseñas ni archivos temporales en Git.
- [ ] Compilar desde un clon limpio del repositorio.
- [ ] Revisar los cambios mediante Pull Request.
- [ ] Etiquetar o registrar la versión entregada.

## Seguimiento del equipo

Para cada tarea, acuerden un responsable, fecha objetivo y criterio de aceptación. No asignen responsabilidades por nombre sin confirmarlo entre los integrantes.
